# 01 — Product Vision

## Elevator pitch

Efficient Machine is a mobile game where a player builds a tiny visual machine on a grid, watches particles flow through it in real time, spots inefficiencies, and rebuilds the layout to beat increasingly demanding contracts.

The fantasy is **not** “own a factory”. The fantasy is:

> “I built this. I understand why it works. I can make it better.”

## Why this has potential

Many casual games offer an immediate action but shallow mastery. Many factory/automation games offer deep mastery but require long sessions, dense UI and expensive content. Efficient Machine aims for the gap:

- rule readable in seconds;
- one-finger portrait input;
- runs well on modest Android devices;
- visually satisfying continuous motion;
- meaningful optimization;
- almost unlimited combinatorial depth;
- content generated from systems rather than handcrafted art/levels.

## Emotional loop

1. **Curiosity** — “What does this new module do?”
2. **Ownership** — “This layout is mine.”
3. **Diagnosis** — “That corner is the bottleneck.”
4. **Experiment** — move/rotate/replace.
5. **Payoff** — OUTPUT jumps visibly.
6. **Near goal** — contract target is close.
7. **Mastery** — player learns principles, not answers.
8. **Reset with purpose** — prestige changes the design space.

## Audience

Primary:
- casual puzzle players;
- idle/incremental players who want more agency;
- optimization/factory-game fans who want a lighter mobile experience.

Secondary:
- players who enjoy “numbers go up” but dislike pure clicking;
- creators who like sharing compact builds and records.

## Product pillars

### 1. Readable
A screenshot must reveal where particles come from and where they go.

### 2. Tactile
Every meaningful optimization must feel good: snap, pulse, acceleration, brighter receiver, stronger haptic.

### 3. Fair
The machine follows deterministic rules. If output is bad, the player can inspect why.

### 4. Deep from interactions
Depth comes from combining simple modules, not from adding dozens of unrelated minigames.

### 5. Persistent
Machines, blueprints, unlocked modules, prestige cores and records survive sessions.

## Anti-pillars

The game must not become:
- a spreadsheet with decorative particles;
- an idle game where player decisions stop mattering;
- a puzzle campaign with one intended solution per level;
- an ad funnel;
- a factory simulator requiring tutorials before fun.
